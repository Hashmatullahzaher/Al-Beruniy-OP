All previously approved business modules — Sales, Collections, Finance, Construction, BOQ, Procurement, Suppliers, Contractors, Warehouse, Expense, HR, Payroll, Documents, Workflow — remain intact. This revision adds, across and around them:

AI CORE — the nine changes in plain language
1 · AI is a system-wide Enterprise Intelligence CoreNot a chatbot bolted on at the end — a control plane that spans every module and grows with each one. BP-20
2 · Every module connects to the AI CoreEach domain publishes events and exposes typed tools; the AI contract strip on every module sheet shows exactly what. BP-03…24
3 · AI knowledge is security-tagged and permission-controlledThe Core may know the enterprise; each person sees only what they are authorized to see. BP-16 · BP-20
4 · LLM providers connect through one Model GatewayAPI key, service account, OAuth or private model — never a direct call from a module. BP-20 · BP-22
5 · Telegram is a governed operating / AI channelQueries, alerts, approval notices, low-risk drafts, secure deep links. No separate business logic, no direct database. BP-22 · MNW
6 · Telegram users are bound to ABOS identitiesOne-time link from a signed-in session; username is never trusted; binding is revocable. BP-02 · BP-23
7 · AI and Telegram cannot bypass Finance, workflow, SoD, permissions or auditAI proposes; humans approve; Finance posts. High-risk actions need step-up or an ABOS deep link. BP-04 · BP-17 · BP-23
8 · Every AI / Telegram action is traceableBack to user, model, sources, tool and resulting transaction — forward and reverse. BP-26
9 · All previous business modules remain intactNo actor, transaction, approval, document, posting, report or audit path was removed. Finance remains the only accounting engine.

How to Read This Package

Connector IDs link processes across sheets (OUT ▸ / IN ◂). New in v1.2: AI-01 AI Core · MG-01 Model Gateway · KP-01 Knowledge Plane · TOOL-01 Typed Tools · MID-01 Machine Identity · TG-01 Telegram Gateway.
Three account types are never mixed: A · User B · Business Party C · Ledger. Telegram binds to Type A; it is not a party. AI provider accounts are not ABOS users; Machine Identity is its own concept.
Arrow semantics (never colour alone): solid = process · thick = financial posting · double = master-data sync · dashed = reference · dotted = notification / audit / AI event · dash-dot = Telegram channel.
Every module sheet carries the 16-facet strip and, new in v1.2, the AI Core & Telegram Contract strip: typed read tools · draft/action tools → workflow · events → Knowledge Plane · Telegram queries & notifications · hard guardrail.
